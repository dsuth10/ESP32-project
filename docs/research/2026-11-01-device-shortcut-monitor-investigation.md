# Opening an application on a selected display: investigation

1 November 2026. Research and design only; no application, device, display configuration or firmware was changed or tested. Existing worktree changes were preserved.

## Finding and suggested direction

A desktop companion action can receive a device shortcut, resolve a teacher-selected display, find or launch an application, move its window, request foreground activation and report the verified outcome. The existing `src/macropad_config.cpp` defines fixed keyboard-combination buttons, and `tools/compose/hotkey_state.py` handles F13–F17 and fallback chords; these existing actions must be preserved. `tools/compose/focus_tracker.py` already contains foreground verification for an existing captured target, but that is not a monitor-aware launcher. General runtime device-profile editing is still a design milestone in `docs/2026-10-21-companion-media-agent-master-plan.md` M7. A dedicated labelled device button is not established without a firmware/profile change; test the host action with a keyboard first.

Provide a companion setup screen with a visual identify overlay on each connected screen, teacher-friendly names such as Classroom display, explicit home/work profiles, application selection and a Test button. Map the role to observed display identity/path and topology, not a saved display number alone. [QueryDisplayConfig](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-querydisplayconfig) exposes active paths; [target information](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/ns-wingdi-displayconfig_target_device_name) may contain friendly names, EDID IDs and a device path. These can be missing, duplicated or change with docking, adapters or virtual displays. Re-identify on ambiguity, and do not silently send a sensitive window to the wrong screen.

On invocation: resolve the configured monitor; resolve a valid application window using application identity, process and window properties, not mutable title alone; apply a defined choice when multiple OneNote windows exist; start the configured application only if needed; wait with a bound for the actual window; restore/move/maximise as configured; request activation; verify placement and foreground separately. Give actionable feedback if either fails. Avoid closing windows, altering notebooks, injecting typing, or assuming a successful launch means the window is on screen. Use the monitor work area, negative coordinates and per-monitor DPI correctly; account for maximised/minimised windows, sleep, hotplug, and remote or virtual desktops. Windows documents [multi-monitor placement](https://learn.microsoft.com/en-us/windows/win32/gdi/positioning-objects-on-multiple-display-monitors) and limits [foreground activation](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow); a successful focus request cannot be assumed. Installation variants of OneNote and the matching/launch policy require local investigation.

## Existing solutions

- [PowerToys Workspaces](https://learn.microsoft.com/en-us/windows/powertoys/workspaces) can capture arrangements, launch them from a shortcut and optionally move existing windows. Application behaviour differs when already running; it launches and then positions windows, which can visibly move. It is a useful comparison and optional proof of concept, not yet verified with this OneNote installation or both locations. [PowerToys source](https://github.com/microsoft/PowerToys/blob/main/src/modules/Workspaces/WorkspacesWindowArranger/WindowArranger.cpp) shows explicit window matching and placement.
- [PowerToys Keyboard Manager](https://learn.microsoft.com/en-gb/windows/powertoys/keyboard-manager) can map a shortcut to an application and choose what to do if running, but app launching alone does not establish target-monitor placement. [FancyZones](https://learn.microsoft.com/en-us/windows/powertoys/fancyzones) manages layout, not by itself the complete OneNote trigger and selection workflow.
- [AutoHotkey](https://github.com/AutoHotkey/AutoHotkey) supports hotkeys and Windows automation and is useful for a quick independent experiment, but adds a second scripting/runtime and configuration surface. Review the exact version and licence before distribution.
- [komorebi](https://github.com/LGUG2Z/komorebi) offers extensive monitor and window management, but its stated current licence restricts work use and redistribution; suitability for this school and distribution is unproven. A whole tiling manager is a larger dependency than this specific use case.
- Windows Win+Shift+Left/Right moves the currently active window between adjacent displays ([Microsoft](https://learn.microsoft.com/en-us/windows/configuration/keyboard-filter/predefined-key-combinations)). It is a manual fallback, not a direct stable mapping to a named display and application.

## Acceptance and open decisions

First prototype using a normal keyboard and a harmless local test window; check two monitors at home with normal, maximised, minimised, closed, multiple-window, disconnected/reconnected and reordered monitor cases, mixed scaling and failed foreground activation. Verify the precise installed OneNote version and multiple-window behaviour, then test with the actual device and the three-monitor work topology. Record local checks, physical device acceptance and classroom acceptance separately. Select the desired behaviour when multiple OneNote windows exist, whether to maximise, and what to do if the intended display is missing. A board trial or write still requires explicit authorisation and the project safety procedure; host testing does not grant it.

The companion already has a pupil-display selector in `tools/compose/board_candidate.py`, which is a useful interface starting point but currently identifies displays by index rather than a durable role. The current Create & Paste profile has an unused sixth slot; activating it still requires a candidate firmware change and its own authorised trial. See the [project integration review](2026-11-01-monitor-shortcut-project-integration.md) for the detailed path and constraints.

The [external research](2026-11-01-monitor-shortcut-external-research.md) provides additional leads; its coordinator review identifies claims that require verification and should not be treated as implementation instructions.
