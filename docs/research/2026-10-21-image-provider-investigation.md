# Image provider investigation: classroom companion

**Retrieved:** 21 October 2026. **Scope:** provider capability and decision evidence for a Windows voice agent that can find or generate an educational image, refine it by conversation, retain named versions, and insert an approved asset at the active cursor. No provider account, key, paid generation, or installation was created. This is provider research only; destination approval and product requirements remain open.

## Recommendation

Keep Groq as the existing conversation/orchestration option if it remains a good fit, but treat its image input as vision (understanding an image), not image creation. The official Groq model catalogue currently lists text-output models, and its vision documentation describes image understanding/OCR; no image-output/generation model or image-generation API was documented in the sources checked. That is a bounded documentation finding, not proof no future/partner offering exists. Route image generation/editing through a separately configured image provider behind a small provider interface.

For a first quality-focused comparison, evaluate **OpenAI GPT Image 2.5 Sunburst** and **Google Gemini 3 Pro Image** against the same water-cycle task. OpenAI is the clearest documented fit for iterative, high-fidelity edits in a conversational context; its Responses API carries image inputs/outputs over multiple turns, while Images API handles direct generation and edits. Google’s Pro Image is explicitly aimed at professional asset production and complex instructions, supports conversational editing, high resolution and reference imagery. Neither vendor documentation guarantees scientific correctness of labels or arrows. Prefer a hand-authored/vector diagram for text and scientific relationships, or require teacher verification before canonical approval; image models can create attractive but wrong diagrams.

The teacher-facing flow should retain a source and version record, display the proposed image before use, and require explicit approval before writing/inserting it. For “find an image”, do not silently treat generated imagery as retrieved licensed material: record whether an asset was generated or sourced, its source URL/attribution/licence when applicable, provider/model, prompt/edit history, timestamp, and approval. No school destination or image library has been confirmed in this investigation.

## Recommended small evaluation: “our water cycle image”

Run this as a controlled, teacher-reviewed bake-off; no real student data is needed. Use one fixed brief: “Create a clear, age-appropriate Australian primary-school water-cycle diagram. Show ocean/lake, Sun, evaporation (water vapour rising), condensation/cloud formation, precipitation falling, and collection/run-off returning water to the body of water. Use readable English labels, arrows with correct direction, uncluttered landscape layout, and no extra processes. Do not add claims beyond these.” Ask each provider for one 16:9 or landscape output at comparable display resolution; log exact model, endpoint, settings, prompt, returned usage/cost, timestamps, and any failures.

Then conduct three conversational edits against the same accepted base candidate: (1) make labels larger and higher contrast, changing nothing else; (2) correct a deliberately introduced wrong arrow/label, preserving composition; (3) ask for a simpler version suitable for a younger class, preserving the six required concepts. Save every result as a separate version; never overwrite the prior candidate. Ask the model to describe its own output only as a secondary check, then have a human independently inspect it.

Score each initial output and edit from 0–2 on: six concept coverage; scientific correctness of labels/arrow directions; label spelling/readability at actual intended print/display size; age-appropriate visual clarity; edit obeyed while preserving requested details; and repeatability/version traceability. Record generation/edit latency from actual runs—do not infer it from vendor claims. Any incorrect process, reversed arrow, misspelling, missing concept, unapproved image write, or lost prior version is a fail for that trial. Keep canonical asset status separate from “generated”; only the user’s explicit approval makes it “our water cycle image”.

If labels/arrows remain unreliable, render the diagram as SVG/HTML from a fixed, teacher-reviewed semantic specification and use the image model only for decorative background/art, keeping textual labels and arrows in deterministic vector/layout code. That gives editable resolution-independent output and makes factual content reviewable before insertion.
